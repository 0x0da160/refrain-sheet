# 判断の記録 — Refrain Sheet Design System v2.0.0

各項目は「問題 → 決定 → 理由 → 捨てた案」の順です。調査は [research.md](research.md)、
値の一覧は各層の説明書（`foundations/docs/foundations.html`・`brand/docs/brand-guidelines.html`・
`app/docs/design-system.html`）、値の出典は `tools/source/*.mjs` にあります。

## 前提：v1.0.0 の再評価で見つかったこと

## D-18 共通基盤・ブランド・アプリの 3 層に分ける

- **問題**：F-9。LP は「読ませる」、アプリは「一日中使わせる」もので、文字の大きさも余白も違って当然です。一方で色・書体・形がずれると、同じ製品に見えません。
- **決定**：
  - **共通基盤**（`foundations/`）：パレット、ブランドの基準色、共通の意味色（light / dark）、書体・太さ・最小サイズ、余白・角丸・線・動き・ブレークポイント・アイコン・影、ロゴとアプリアイコン。
  - **ブランド**（`brand/`、ガイドライン v3.0）：LP・ドキュメント・ストア掲載。流体的な文字、ページの幅、44px のボタン、見本の影、ロゴの使い方、画像、文言と名前。クラス接頭辞 `rb-`。
  - **アプリ**（`app/`）：キャンバスの色、hybrid テーマ、文書の色、4 段の文字、密度、グリッド、重なり順、部品。クラス接頭辞 `rs-`。
  - 層は基盤に**足すだけ**で、上書きしません。
- **理由**：両方で同じ意味を持つもの（緑＝操作・現在地、紙とインク、400/700、角丸の段階）は 1 か所にあれば、ずれようがありません。文字のスケールのように読み方で変わるものは、層ごとに持つ方が素直です。
- **捨てた案**：v1 のように 1 つの文書（LP に不要な規定が増え続ける）。完全に別のシステムにする（色の値が二重管理になる。F-10 がまさにそれ）。

## D-19 トークン名：`chrome-*` を `bg-*`・`fg-*`・`border-*` に、線の太さを `stroke-*` に

- **問題**：`chrome`（アプリの枠）は LP にない概念です。また v2 の途中版では、色の `--border-strong` と線の太さの `--border-strong` が同じ名前でした。
- **決定**：`--bg-page` `--bg-surface` `--bg-raised` `--bg-sunken` `--bg-hover` `--bg-pressed`、`--fg-default` `--fg-muted` `--fg-subtle`、`--border-default` `--border-strong` `--border-control`。線の太さは `--stroke-thin` `--stroke-medium` `--stroke-thick`。
- **理由**：LP とアプリで同じ名前をそのまま使えます。アプリの現行の `--bg` `--text` `--border` とも衝突しません（移行時に 2 つを並べて置けます）。文字サイズの `--text-*` と文字色の混同も避けられます。

## D-01 文字：アプリは本文 14px・補助 12px、下限は日本語も 12px

- **問題**：v1 の本文 16px・下限 14px は、業務用の道具には大きすぎます（F-1）。v2 の途中版では日本語の下限を 13px にしていましたが、セルを 12px に据え置く決定（D-03）と合わせ、利用者の判断で下限を 12px に統一しました。
- **決定**：caption 12 / body 14 / title 16 / heading 20px。行送りは 16 / 20 / 24 / 28px。12px は日本語にも使えます。粗いポインタでは caption 14px・body 16px に上げます。LP（ブランド層）は流体的に 12〜52px。
- **理由**：Fluent・Carbon・Primer・Atlassian・Material の 5 つがそろって本文 14px・補助 12px です（[research.md](research.md) §1、パッケージで確認）。12px と 13px を両方持つと、段階が細かすぎて使い分けられません。
- **捨てた案**：v1 のまま 16px。日本語だけ 13px を下限にする（セルの 12px と食い違う）。

## D-03 セルの文字は 12px のまま

- **問題**：v2 の途中版では、表計算ソフトの既定に合わせて 13px を提案していました。
- **決定**：`--grid-font-size: 12px`（× 表示倍率）。アプリの現行値のままです。
- **理由**：(1) 表計算ソフトの既定は 10pt（13.3px：LibreOffice Calc・Google スプレッドシート）と 11pt（14.7px：Excel）に分かれており、13px が標準というわけではありません（[research.md](research.md) §2）。(2) 既定の行高 24px・列幅 104px・保存済みの列幅がこの値を前提に決まっており、変えると既存の文書で「列幅に合わせた」列の文字が切れます。(3) BIZ UDGothic は小さいサイズでも読めるよう設計された書体で、表示倍率で拡大できます。

## D-02 太さは 400 と 700 だけ

- **決定**：v1 を継承し、LP とアプリの両方に適用します。ブランドガイドライン v2.0 の 500・600、LP の 800 は廃止します（F-2・F-10 の解決）。ロゴタイプの 500 はアウトライン化された図形なので対象外です。
- **理由**：BIZ UD に 500・600・800 はなく、実際には 400 か 700 で描画されています。

## D-20 大文字の英字ラベルの字間は 0.08em

- **問題**：ブランドガイドライン v2.0 は 0.08em、DS v1.0 は根拠を示さずに 0.04em、LP の実装は 0.14em で、3 つの値がありました。
- **決定**：0.08em（`--tracking-caps`、共通基盤）。日本語には使いません。
- **理由**：ブランドの持ち主であるガイドラインの値を採りました。0.14em は、12〜14px の等幅書体では単語がばらけて見えます。

## D-04 密度：compact / standard / comfortable。「表示」メニューから切り替える

- **決定**：バー 28 / 32 / 40、バー内のコントロール 24 / 28 / 32、フォーム 28 / 32 / 40、内側余白 8 / 12 / 16。粗いポインタでは 44px を下限にします。文字サイズとグリッドは変えません。**「表示」メニューに切り替えを出すことを、利用者が決定しました。**設定は端末ごとに保存し、文書には保存しません。
- **理由**：バーは 4〜5 本あるため、1 本あたり 4px の差が画面全体の行数に直結します。standard のバー 32px はアプリの現状と同じです。compact でも 24px 以上なので WCAG 2.5.8 を満たします。
- **名前**：v1 の comfortable（36px）とは値が違うため、名前を再利用せず standard としました。

## D-05 コントロールの高さを 2 系統にする

- **決定**：バー・メニュー・タブ・リストの行は `--control-h`、ダイアログとパネルのボタン・入力欄は `--field-h`。
- **理由**：表計算では、バーの中は詰め、決定を伴うダイアログはゆったりさせるのが実用的です。

## D-06 余白：4px 基準に 2px・6px、LP 用に 80px・96px

- **決定**：0, 2, 4, 6, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 96px（共通基盤）。
- **理由**：Fluent と Atlassian も 2px・6px を持っています。80px・96px は LP のセクションの区切りに使います。

## D-07 角丸：2 / 4 / 6 / 8 / 12 / 16px

- **決定**：アプリはメニュー 8・ダイアログ 12。LP はボタン 8・カード 12・画面の額縁 16。セルは 0（アプリ層）。
- **理由**：同心の角丸（メニュー 8 = 項目 4 + 内側余白 4）から決めました。Fluent（最大 8）と Atlassian（最大 16）の範囲に収まります。LP の現行値 10・14px は 12・16px に揃えます。

## D-08 色：v1 の色相は変えず、段階と用途を足す

- **決定**：ブランド色と既存の段階はバイト単位で維持します。追加は `ink-150`・`ink-250`（暗いテーマの副次テキストを 4.5:1 にするため）と、`violet`・`teal`（数式の参照と構文色）です。ブランドの基準色 5 つ（green・paper・mist・leaf・ink）には固定の名前（`--brand-*`）を付けました。
- **意味トークンの追加**：`bg-hover` / `bg-pressed`、`inverse-*`、`danger-subtle` / `warning-subtle` / `info-subtle`（F-3 の解決）、キャンバスの状態一式（F-5 の解決）。
- **補助テキスト**：`fg-subtle` もすべての背景で 4.5:1 にしました（F-4 の解決）。用途はプレースホルダだけです。

## D-09 キャンバスと枠の色を混ぜない

- **決定**：キャンバス（グリッド・ソースエディタ）の中では `canvas-*`・`state-*`・`ref-*`・`syntax-*` だけを使い、枠では使いません。
- **理由**：hybrid テーマが成り立つ唯一の条件です。F-3 は、この規則がなかったために起きました。

## D-10 範囲選択は半透明の塗り

- **決定**：`canvas-range-fill` は accent 色の 12%（dark 16%）です。検索一致の塗りは背景画像の層に重ね、利用者の塗り色を置き換えません。
- **理由**：利用者がセルに付けた塗り色が、選択中も見えている必要があります。

## D-11 セル状態は四隅と辺を予約する

- **決定**：右上＝コメント、左下＝数式、右下＝フィルハンドル、行頭側の辺＝編集済みの変更バー。エラーは太字、解析不能は波線、削除は取り消し線。
- **理由**：F-6 の解決と、色だけに頼らないため（WCAG 1.4.1）。コメントの印は amber から blue に変え、amber は「編集済み（未保存）」専用にします。配置と色は [ip-risk-policy.md](../../../knowledge/decisions/ip-risk-policy.md) に沿ってこのプロジェクトで決めたものです。

## D-12 数式の参照は 4 色 × 4 種類の線

- **決定**：blue・violet・amber・teal と、実線・破線・点線・二重線。
- **理由**：アプリの現行の参照色は 1 番と 2 番がどちらも緑系で見分けにくい状態でした。赤は「エラー」と誤読されるため使いません。

## D-13 文書の色はテーマから独立させる

- **決定**：利用者が付けた文字色・塗り色・条件付き書式はデータとして扱い、どのテーマでもそのまま描画します。色の選択には 65 色の見本を使います。
- **理由**：テーマの切り替えで文書の見た目が変わると、「CSV を勝手に変えない」という約束と同じ種類の信頼を損ないます。アプリの条件付き書式の既定色（`#FFC7CE`・`#63BE7B`）は、見本から選んだ値に置き換えることを推奨します。

## D-14 重なり順をアプリの層構造に合わせる（アプリ層）

- **決定**：raised 10 / panel 100 / popover 120 / menu 150 / submenu 160 / modal 200 / overlay 250 / toast 300 / tooltip 400。
- **理由**：アプリの実際の順序（`knowledge/ui/theming-and-visual-system.md`）をトークン化しました（F-8）。LP はヘッダの固定だけなので、共通基盤には置いていません。

## D-15 アイコン：Lucide、描画上の線幅 1.5px

- **決定**：ブランドガイドラインの「線幅はサイズによらず 1.5px」を `vector-effect: non-scaling-stroke` で実現します（共通基盤）。
- **理由**：アプリは Lucide の既定値（16px 表示で約 1.33px）で描いており、ガイドラインと一致していません。

## D-16 生成ツールをリポジトリに置き、DTCG 形式でも出力する

- **決定**：`tools/source/{foundations,app,brand}.mjs`（値）と `tools/build.mjs`（生成・監査・検証。Node のみで依存なし）。出力は CSS と、各ファイルに `$schema` を付けた Design Tokens Format Module 2025.10 の JSON です。
- **理由**：F-7 の解決。仕様の原稿で、色・寸法・文字・影の書式が仕様どおりであることを確認しました（[research.md](research.md) §4）。

## D-17 コントラストの判定は WCAG 2.2

- **決定**：文字 4.5:1、UI 部品と状態の印 3:1。半透明のトークンは重なる背景と合成してから測ります。共通基盤 76 項目（38 組 × 2 テーマ）、アプリ 96 項目（32 組 × 3 テーマ）、ブランド 6 項目（3 組 × 2 テーマ）を監査し、1 つでも割るとビルドが失敗します。
- **理由**：APCA は WCAG 3 の草案で未確定です。

## D-21 LP の表現の調整（ブランド層）

- **決定**：太さを 700 に（D-02）、英字ラベルの字間を 0.08em に（D-20）、ボタンの角丸 8px・カード 12px・画面の額縁 16px に（D-07）、ボタンは 44px（ヒーローは 52px）でホバーしても持ち上げない、色は共通基盤のトークンだけ。流体的な文字サイズ・最大幅・セクションの余白は現行値のまま。
- **理由**：F-10 の解決。LP の文字組みとレイアウトは読み物としてよく調整されているので残し、基盤からずれている部分だけを直します。

## 決定済み（2026-09-26、利用者の判断）

1. セルの文字は 12px のまま。文字の下限は日本語も 12px（D-01・D-03）。
2. ブランドガイドラインとアプリのデザインシステムを分け、共通部分は共通基盤に統合する（D-18）。
3. 密度の切り替えを「表示」メニューに出す（D-04）。
4. LP から先に適用する（[migration.md](migration.md) §6、適用済み）。
5. LP の本文は 16〜18px の流体のまま（D-22）。

## D-22 LP の本文は 16〜18px の流体を維持する

- **決定**：`--brand-text-body` は `clamp(1rem, 0.95rem + 0.25vw, 1.125rem)` のまま。
- **理由**：LP は読み物です。スマートフォンでは 16px、広い画面では画面から離れて読まれることが多いため 18px まで大きくします。どの幅でもデジタル庁の「本文 16px 以上」を満たし、現行の LP で調整済みの値なので、見た目も変わりません。

## D-23 LP のスクロール時の出現は不透明度だけ

- **決定**：`.reveal` は 320ms（`--duration-slow`）の不透明度の変化だけにし、下から滑り込む動き（14px・600ms）をやめました。
- **理由**：「動くのは開閉とフィードバックだけ」（共通基盤）。出現の合図は残しつつ、ページの中身が動いて見えることを避けます。

## D-24 フォントの連鎖はアプリで検証済みのものを共通基盤にする

- **決定**：`--font-ui` と `--font-data` を、アプリが v2.0.0 以前から使って検証してきた連鎖（Meiryo UI・MS UI Gothic・Yu Gothic などの Windows の代替と、`BIZ UDゴシック`・`ＭＳ ゴシック` の和名を含む）に置き換えます。アプリは独自の連鎖を持たず、既定のスプレッドシートのフォントも `--font-data` を参照します。
- **理由**：Windows（主な対象）の古い環境でも同じ字形に落ちることをアプリで確認済みです。LP では、先頭の BIZ UDPGothic・Yu Gothic UI・Hiragino Sans・Noto Sans JP が見つかる環境では表示は変わりません。どれもない環境の最後の代替は `system-ui` から `sans-serif` に変わります（アプリと同じ）。

## D-25 ソースエディタの文字は本文サイズ

- **決定**：JSON・YAML・Markdown・テキストのエディタは `--text-body`（14px）。表示倍率では拡大しません。JSON と YAML は `--font-code`、Markdown とテキストは利用者が選んだスプレッドシートのフォントです。
- **理由**：エディタには表示倍率の仕組みがなく、グリッドの 12px では文章を編集するには小さすぎます。文章は、表と同じ字形で読めることを優先します。

## D-26 縞模様の行は「表示」メニューでオンにする

- **決定**：アプリの縞模様は既定でオフ。「表示 > 行を交互に色分け」でオンにでき、端末ごとに保存します。
- **理由**：縞は利用者がセルに付けた塗り色と競合するため、既定ではオフにします（アプリのデザインシステム §グリッド「約束事」）。v2.0.0 以前のアプリは縞を常に表示していたので、長い行を目で追いたいときのために戻す手段を残します。
