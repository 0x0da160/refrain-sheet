# 判断の記録 — Refrain Sheet Design System v2.0.0

各項目は「問題 → 決定 → 理由 → 捨てた案」の順です。調査は [research.md](research.md)、
値の一覧は [design-system.html](design-system.html)、値の出典は `tools/source.mjs` にあります。

## 前提：v1.0.0 の再評価で見つかったこと

| # | 見つかったこと | 影響 |
| --- | --- | --- |
| F-1 | 寸法が汎用 Web 向け（本文 16px、コントロール 36px、行高 34px）で、表計算の密度に合わない | アプリは寸法を採用できず、色とフォントファミリーだけが適用された（0.8.5）。フォント 9〜13px が約 35 か所、`font-weight: 600` が 22 か所、独自の余白・角丸・z-index が残った |
| F-2 | ブランドガイドライン v2.0 と DS v1.0 の文字規定が矛盾（ガイドラインは Inter・UI 13〜14px・ウェイト 500/600、DS は BIZ UD・最小 14px・400/700） | どちらに従えばよいか決められない |
| F-3 | 警告・エラーのバナーが、シート側の `state-*` を使っていた | hybrid テーマ（シェルが暗く、シートが明るい）では、暗い文字色が明るい塗りの上に来るはずが逆になり、警告文が 1.53:1 まで落ちる |
| F-4 | 「補助テキスト」を 3:1 で許容していた | WCAG 2.2 の文字の基準（4.5:1）を満たさない |
| F-5 | 数式の参照色、検索一致、数式・コメント・エラーの印、構文色、文書の色など、表計算に必要な状態のトークンがない | アプリ側に独自の値（`#2563EB` 系の `rgba()` など）が残る |
| F-6 | アプリでは数式の印とコメントの印がどちらもセルの右上にある | 両方を持つセルで片方が消える |
| F-7 | 生成ツール（`tools/palette.py` ほか）がリポジトリにない | 誰も再生成・検証できない |
| F-8 | 重なり順（sticky 100〜tooltip 600）がアプリの実際の層構造と対応していない | パネルの隣でメニューを開くと、下に潜る順序になり得る |

---

## D-01 文字：UI の本文 14px、日本語の下限 13px、12px は英数字専用

- **問題**：v1 の本文 16px・下限 14px は、業務用の道具には大きすぎます（F-1）。一方で、日本語を 12px にすると画数の多い漢字が潰れます。
- **決定**：caption 12 / meta 13 / body 14 / title 16 / heading 20 / display 28px。行送りは 16 / 18 / 20 / 24 / 28 / 36px（すべて 4 の倍数）。12px は英数字だけの文字列（ショートカット・件数・単位）に限ります。粗いポインタでは body 16px、meta 14px に上げます。
- **理由**：主要な業務系デザインシステムは本文 14px・補助 12px に収束しています。日本語はデジタル庁の基準（14px 未満は原則不可）より 1px 緩めていますが、読み物ではなく UI ラベルであり、BIZ UD が小さいサイズ向けの UD 書体であることを根拠にしています。rem で定義するため、既定の文字サイズを大きくしている人には比例して大きく表示されます。
- **捨てた案**：v1 のまま 16px（グリッドの表示行数が大きく減る）。すべて 13px（ダイアログの説明文が読みにくい）。

## D-02 ウェイトは 400 と 700 だけ

- **決定**：v1 を継承します。ブランドガイドラインの 500・600 は、UI テキストには適用しません（F-2 の解決）。
- **理由**：BIZ UD に 500・600 はありません。アプリの `font-weight: 600` は実際には 700 で描画されています。ロゴタイプの 500 はアウトライン化された図形なので対象外です。

## D-03 セルの文字 13px、行高 24px

- **決定**：`--grid-font-size: 13px`、`--grid-row-h: 24px`。いずれも表示倍率（`--sheet-zoom`）を掛けます。アプリは現在 12px です。
- **理由**：表計算の既定値として一般的な 10pt（約 13.3px）に近く、24px の行に 1px の罫線と上下の余白を引いた 17px の行送りへ無理なく収まります。
- **注意**：自動列幅の計測結果が変わるため、アプリへの適用は独立した変更として扱います（[migration.md](migration.md)）。

## D-04 密度：compact / standard / comfortable、既定は standard

- **決定**：バー 28 / 32 / 40、バー内のコントロール 24 / 28 / 32、フォーム 28 / 32 / 40、内側余白 8 / 12 / 16。粗いポインタでは 44px を下限にします。文字サイズとグリッドは変えません。
- **理由**：バーは 4〜5 本あるため、1 本あたり 4px の差が画面全体の行数に直結します。standard のバー 32px はアプリの現状（`--bar-height: 32px`）と同じなので、移行の衝撃が最も小さくなります。compact でも 24px 以上なので、WCAG 2.5.8 を満たします。
- **名前**：v1 の comfortable（36px）とは値が違うため、名前を再利用せず standard としました。
- **捨てた案**：密度でグリッドの行高も変える（行高は文書側の表示状態で、自動の列幅・折り返しの計算に影響する。拡大率で扱う）。

## D-05 コントロールの高さを 2 系統にする

- **決定**：バー・メニュー・タブ・リストの行は `--control-h`、ダイアログとパネルのボタン・入力欄は `--field-h`。
- **理由**：表計算では、バーの中は詰め、決定を伴うダイアログはゆったりさせるのが実用的です。1 つの高さで両方を満たすことはできません。

## D-06 余白：4px 基準に 2px・6px を追加

- **決定**：0, 2, 4, 6, 8, 12, 16, 20, 24, 32, 40, 48, 64px。名前は `--space-0-5`（2px）と `--space-1-5`（6px）を追加し、v1 の名前と値はすべて残します。
- **理由**：メニューの項目間やバーの内側では 2px と 6px が必要です。アプリはすでにこの刻みを使っています（#594）。

## D-07 角丸：lg 10→8px、xl 14→12px

- **決定**：cell 0 / xs 2 / sm 4 / md 6 / lg 8 / xl 12 / full。
- **理由**：同心の角丸の規則から決めました。メニュー（lg 8）は、項目（sm 4）に内側余白 4 を足した値です。密な UI では 10〜14px が柔らかすぎ、道具らしさを損ないます。
- **互換**：値の変更なので、メジャーバージョンを上げました。

## D-08 色：v1 の色相は変えず、段階と用途を足す

- **決定**：ブランド色と既存の段階はバイト単位で維持します。追加は `ink-150`・`ink-250`（暗いテーマの副次テキストを 4.5:1 にするため）、`violet`・`teal`（数式の参照と構文色）です。
- **意味トークンの追加**：`chrome-hover` / `chrome-pressed`（状態の塗りを明示）、`inverse-*`（ツールチップ・トースト）、`danger-subtle` / `warning-subtle` / `info-subtle`（シェル用のバナー。F-3 の解決）、キャンバスの状態一式（F-5 の解決）。
- **補助テキスト**：`chrome-text-subtle` もすべての背景で 4.5:1 にしました（F-4 の解決）。用途はプレースホルダだけに絞り、ショートカット表記には `chrome-text-muted` を使います。

## D-09 chrome と canvas の分離を規則にする

- **決定**：キャンバス（グリッド・ソースエディタ）の中では `canvas-*`・`state-*`・`ref-*`・`syntax-*` だけを使い、シェルでは使いません。
- **理由**：hybrid テーマが成立する唯一の条件です。F-3 は、この規則がなかったために起きました。監査にも、シェルとキャンバスをまたぐ組み合わせを入れていません。

## D-10 範囲選択は半透明の塗り

- **決定**：`canvas-range-fill` は accent 色の 12%（dark 16%）です。v1 の不透明な `canvas-selection` は、見出しなど単独の要素に限ります。検索一致の塗りは背景画像の層に重ね、利用者の塗り色を置き換えません。
- **理由**：利用者がセルに付けた塗り色が、選択中も見えている必要があります。

## D-11 セル状態は四隅と辺を予約する

- **決定**：右上＝コメント、左下＝数式、右下＝フィルハンドル、行頭側の辺＝編集済みの変更バー。エラーは太字、解析不能は波線、削除は取り消し線。
- **理由**：F-6 の解決と、色だけに頼らないため（WCAG 1.4.1）。コメントの印は、状態・警告を表す amber から情報を表す blue に変えました。amber は「編集済み（未保存）」専用にします。
- **独自性**：印の配置と色は、[ip-risk-policy.md](../../../knowledge/decisions/ip-risk-policy.md) に沿ってこのプロジェクトで決めたものです。特定製品の配置を再現していません。

## D-12 数式の参照は 4 色 × 4 種類の線

- **決定**：blue・violet・amber・teal と、実線・破線・点線・二重線の組み合わせ。
- **理由**：アプリの現在の参照色は 1 番と 2 番がどちらも緑系で、見分けにくい状態でした。色相を 90° 近く離し、線の種類でも区別します。赤は「エラー」と誤読されるため使いません。

## D-13 文書の色はテーマから独立させる

- **決定**：利用者が付けた文字色・塗り色・条件付き書式はデータとして扱い、どのテーマでもそのまま描画します。色の選択には 9 色相 × 7 段階と白・黒の見本（65 色）を使います。条件付き書式の既定値はパレットから選びました。
- **理由**：テーマの切り替えで文書の見た目が変わると、「CSV を勝手に変えない」という製品の約束と同じ種類の信頼を損ないます。見本は段階ごとに明度を揃えているため、表のどこに置いても色の重さが揃います。
- **補足**：アプリの条件付き書式の既定色（`#FFC7CE`・`#63BE7B`）は、この見本から選んだ値に置き換えることを推奨します（[migration.md](migration.md)）。

## D-14 重なり順をアプリの層構造に合わせる

- **決定**：raised 10 / panel 100 / popover 120 / menu 150 / submenu 160 / modal 200 / overlay 250 / toast 300 / tooltip 400。
- **理由**：アプリの実際の順序（`knowledge/ui/theming-and-visual-system.md` の「Stacking order」）をトークン化したものです。メニューは docked パネルより上、ブロックする overlay はメニューより上に来ます（F-8 の解決）。

## D-15 アイコン：Lucide、16px、描画上の線幅 1.5px

- **決定**：ブランドガイドラインの「線幅はサイズによらず 1.5px」を、`vector-effect: non-scaling-stroke` で実現します。
- **理由**：アプリは Lucide の既定値（viewBox 上で 2 = 16px 表示で約 1.33px）で描いており、ガイドラインと一致していません。

## D-16 生成ツールをリポジトリに置き、DTCG 形式でも出力する

- **決定**：`tools/source.mjs`（値）と `tools/build.mjs`（生成・監査・検証。Node のみで依存なし）。出力は CSS と、Design Tokens Format Module 2025.10 の JSON です。
- **理由**：F-7 の解決。2025 年 10 月に DTCG 形式の安定版が出て、主要なデザインツールが対応しています。
- **捨てた案**：v1 のように CSS だけを配る（デザインツールとの往復ができない）。`light-dark()` で 1 回だけ書く（hybrid を表現できない。[research.md](research.md) §3）。

## D-17 コントラストの判定は WCAG 2.2

- **決定**：文字 4.5:1、UI 部品と状態の印 3:1。半透明のトークンは重なる背景と合成してから測ります。210 項目（70 組 × 3 テーマ）を監査し、1 つでも割るとビルドが失敗します。
- **理由**：APCA は WCAG 3 の草案で未確定です。

## 未解決（人の判断が必要）

1. **グリッドの文字を 12px から 13px に上げるか**（D-03）。自動列幅と画面のスクリーンショット（ランディングページ）が変わります。
2. **ブランドガイドライン v2.0 の文字の節を改訂するか**（F-2）。v2 の DS はガイドラインより優先すると宣言していますが、ガイドライン側の記述（Inter、500/600）は残っています。
3. **密度の設定をアプリの UI に出すか**。トークンは用意しましたが、「表示」メニューに項目を足すかどうかは製品の判断です。
