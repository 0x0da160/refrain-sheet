# Additional feature requirements / 機能追加要求

**Status: draft (2026-09-28). A requirements list, not an implementation order: priority, scope, release split and order are undecided. No code is changed by this document.**

## English (summary)

The maintainer's full list of proposed additions to Refrain Sheet, recorded so
later work can be split into Issues. It covers whole-file RSF encryption,
per-sheet protection, sheet tab colors, vertical tabs and nested sheet
folders, a new "grid paper" sheet kind, per-run fonts and a customizable
toolbar, shapes, charts and images, Markdown WYSIWYG, print and PDF,
version-history diff highlighting, schemas and validation, a SQL query
builder, co-editing and more cloud storage, and a CSV-only minimal edition.

Decisions the maintainer made on it (2026-09-28):

- Co-editing ships in the hosted build only, as an explicit exception like
  Google Drive sync, and is compiled out of the `file://` build.
- Whole-file encryption and "unreadable until unlocked" sheet protection share
  one encryption format, with per-sheet passwords. The concrete crypto design
  is high-risk under `CLAUDE.md` and needs human approval.
- Shapes, charts and images: each sheet keeps an object list; image bytes are
  stored once per file and referenced.
- Formulas that reference a locked sheet show an error until it is unlocked.
- Deleting a sheet folder deletes its sheets, with confirmation and undo.
- Schema and the existing data validation are unified; validation becomes
  persisted in RSF and follows row and column insert and delete.
- The SQL query builder is a GUI on the existing read-only SQL panel.
- Print and PDF use the browser's print; no new dependency.
- Markdown WYSIWYG is a mode on the Markdown sheet, still saved as Markdown.
- The minimal edition is CSV editing only (no RSF, SQL, diff or Drive).
- The next cloud storage after Google Drive is OneDrive, hosted build only.

## 日本語

「要求仕様」はオーナーが作成したドラフトの原文です。「決定事項」と「現行コードとの突き合わせ」は、2026-09-28 にこのドラフトをもとに整理したものです。

### 決定事項（オーナーが選択カードで決定、2026-09-28）

- 2026-09-28 共同編集: **ホスト版のみ**。Google Drive 連携と同じく、ホスト版だけで有効な明示的例外とする。file:// 版からはコード自体を取り除き、check:dist で検査する。
- 2026-09-28 暗号化とシート保護: **共通の暗号化**。ファイル全体の暗号化と「解除まで読めない」シート保護を同じ暗号化形式の上に作り、シートごとに別のパスワードを設定できるようにする。暗号方式は CLAUDE.md の高リスク区分に当たるため、設計時にあらためて人の承認を得る。
- 2026-09-28 図形・グラフ・画像の RSF 保存: **画像はファイル共通**。各シートがオブジェクト一覧（位置・重なり順・ロック・グループ）を持ち、画像の中身はファイル単位で共通保存して参照する（重複を避ける）。
- 2026-09-28 ロック中で読めないシートへの数式参照: **エラーを表示**。解除するまで参照しているセルはエラーを表示し、解除後に再計算する。前回の計算結果は見せない。
- 2026-09-28 シートの入ったフォルダの削除: **シートごと削除**。確認を出したうえで、中のシート（とサブフォルダ）をまとめて削除する。Undo で元に戻せる。
- 2026-09-28 スキーマと入力規則: **統合する**。入力規則も RSF に保存し、行や列の挿入・削除に追従させる。スキーマは列単位の規則として同じ仕組みに載せる。
- 2026-09-28 SQL クエリビルダー: **既存パネルに GUI**。今の読み取り専用 SQL パネルに、画面で組み立てる操作を追加する。結果は新しいシートに書き出せる。更新 SQL と外部 DB 接続は含めない。
- 2026-09-28 印刷・PDF: **ブラウザの印刷**。印刷用のページを組んでブラウザの印刷機能に渡し、PDF はブラウザの「PDF に保存」で作る。ページ設定（対象シート・範囲・用紙・向き・拡大縮小・改ページ）はアプリ側に用意する。新しい依存は追加しない。
- 2026-09-28 Markdown WYSIWYG: **シートにモード追加**。Markdown シートに WYSIWYG モードを加え、ソース表示と切り替えられるようにする。保存は今と同じ Markdown テキスト。セル内 Markdown は対象外。
- 2026-09-28 CSV 編集専用ミニマル版: **CSV 編集だけ**。読み込み・編集・検索・並べ替え・フィルタ・保存に絞り、RSF・SQL・比較・Drive は外す。CSV の保存結果が通常版と一致することを試験する。
- 2026-09-28 次のクラウドストレージ: **OneDrive**。Drive と同じく、ホスト版だけの明示的な例外として追加する。

#### まだ決まっていないこと

- 読めないシートで隠すメタデータの範囲（シート名以外）、検索・履歴・出力での扱い
- 共同編集の参加者・権限・競合・同期の詳細
- 暗号方式の具体（高リスク扱い、設計時に承認が必要）
- 全要求の優先順位・スコープ・リリース分割・順序

#### 1. 共通原則・既存機能との境界

##### 確定

- CSVの書式保持を損なう装飾・図形・画像・Markdown・スキーマ等の追加機能はRSF側で扱う。CSV編集専用ミニマル版は別の配布案とする。
- 共同編集は通常のローカル完結動作から分け、利用者が明示的に有効化する別モードとする。
- 保存、名前を付けて保存、保存ショートカット、未保存変更の警告等は既存機能として扱い、今回の追加機能として重複計上しない。各追加機能と保存・Undo/Redo等の既存操作との連携は必要に応じて別途定義する。

##### 提案

- 追加機能が既存のCSVのバイト保持保証を変更しないことを回帰試験で確認する。
- RSF形式の変更、暗号化、画像埋め込み、共同編集は互換性・データ消失・機密性への影響を個別にレビューする。
- クラウド連携や共同編集の通信要件を、通常のローカル完結動作の保証と混同しない表示・文書にする。

#### 2. RSFファイル全体の暗号化

##### 確定

- パスワードを必須の解除手段とする。鍵ファイルやパスキー等は今回の必須要件とせず、復旧鍵も設けない。パスワードを失った場合は復旧できない。
- 暗号化の初期状態はオフ。保存時または後から利用者が明示的に有効化できる。
- パスワード入力前にはシート名・履歴を含むRSFファイル内の内容を見せない。外部のファイル名はこの対象外。
- 暗号化済みRSFを通常保存しても暗号化を維持する。暗号化を外して保存する場合は明示操作を必要とする。
- 開いている暗号化済みRSFのパスワードは、現在のパスワードを確認してから変更できる。

##### 提案・受け入れ観点

- 誤ったパスワード、読込失敗、破損時には復号済みデータの一部を表示せず、元ファイルを自動上書きしない。
- 暗号化を有効化する前に「パスワードを失うと復旧できない」ことを表示する。
- 暗号化範囲に履歴、埋め込み画像、図形・グラフ、Markdown、スキーマ等のRSF内データが漏れなく含まれることを試験する。

#### 3. シート単位の保護

##### 確定

- 各シートで「保護なし」「解除まで内容を読めない」「閲覧はできるがシート内の編集を制限する」を選べる。
- シート保護のパスワードはファイル全体用とは別にでき、シートごとに異なるパスワードを設定できる。
- 内容を読めないシートでも、シート名とタブは表示する。セル等の内容は解除まで隠す。
- 閲覧のみの制限はシート内全体の値・数式・書式等の変更に適用し、編集できるセル範囲の指定は設けない。
- シート名の変更・移動・削除を防ぐ「シート構成の保護」は今回の要求から外し、別途扱う。内容を読めない暗号化と編集制限は異なる機能である。

##### 提案・受け入れ観点

- 保護状態はメニュー、ショートカット、貼り付け、ドラッグ等の操作経路で一致させる。
- 保護された内容を検索結果、履歴プレビュー、印刷、PDF、画像書き出し、クリップボード、グラフ参照等から迂回して表示しない。
- 保護されたシートの解除後に何を閲覧・編集・出力できるかを、保護方式ごとに定義する。

#### 4. シートの整理と方眼紙シート

##### 確定

- シートタブの色は既定の色候補からも、カラーピッカーの任意色からも選べる。
- シートタブは横並びと、画面左側に表示する縦並びを切り替えられる。
- シート用フォルダは複数階層に対応する。各シートが所属できるフォルダは最大一つで、未所属のシートも許す。
- 方眼紙は通常のRSF/CSVグリッドの表示モードではなく、RSF内に作る別種の「方眼紙シート」である。帳票、画面イメージ、ワイヤーフレーム等の作成に用いる。
- 方眼紙シートは正方形のマス目に合わせた配置・サイズ変更を基本とし、文字はセルへの直接入力ではなく、複数マスにまたがるテキストボックスで入力する。

##### 提案・受け入れ観点

- フォルダ変更だけでシートのデータや参照式を書き換えない。フォルダを削除する際の所属シートの移動先と警告を定義する。
- 方眼紙シートは通常の計算グリッドとシート種別が判別できるようにし、保存・再読込で配置が維持されることを確認する。

#### 5. フォントとツールバー

##### 確定

- 通常のRSFシートのセル、および方眼紙シートのテキストボックスで、文字全体・選択した一部分のフォントサイズを変更できる。
- フォント選択肢には `queryLocalFonts` 等で取得できた端末上の一覧と、あらかじめ用意する主要フォント候補を使う。フォント名の手入力は設けない。
- 指定フォントが別端末にない場合、表示のみ代替フォントにし、RSFに保存されたフォント指定は維持する。
- ツールバーは表示する操作を選択・並び替えできる。設定は端末・ブラウザ側に保存し、RSFには含めない。

##### 提案・受け入れ観点

- ローカルフォント一覧を取得できない環境でも、主要候補から選択できる。
- ツールバー設定を初期化する操作を用意し、端末間でRSFを移動してもファイル内容がツールバー設定に左右されないことを確認する。

#### 6. 図形・グラフ・画像

##### 6.1 種類、配置と描画

###### 確定

- 図形・グラフ・画像を通常のRSFシートと方眼紙シートの両方に配置できる。通常シートでは自由な位置・サイズとセルへのスナップに対応し、方眼紙シートではマス目に合わせる。
- 図形の初期対応は四角形、円・楕円、直線、矢印、テキストボックス。塗りつぶし色、線の色・太さ、文字書式を編集できる。
- グラフの初期対応は棒、折れ線、円。通常のRSFシートの連続したセル範囲を参照し、値の変更時に自動更新する。参照範囲の変更、系列の行・列切替、種類の変更、タイトル・凡例・軸ラベル・系列色の変更、データラベルの表示切替に対応する。離れた複数範囲の指定は初期対象外。
- 画像入力はPNG、JPEG、SVG、WebPとクリップボード貼り付けに対応し、RSF内に埋め込む。標準で縦横比を維持し、必要に応じて個別変更、トリミング、回転ができる。図形も回転できる。

##### 6.2 共通操作、コピーと参照

###### 確定

- 前面・背面への移動、重なり順の変更、複数選択、異種オブジェクトのグループ化、グループ内の個別編集、位置揃え・等間隔配置、ガイド線と吸着に対応する。
- ドラッグと矢印キーで位置を調整できる。プロパティから位置・幅・高さを数値指定できる。通常シートではピクセル／ミリメートルを切り替え、方眼紙シートではマス目単位も使える。
- オブジェクトには名前を付け、一覧から選択、表示・非表示、重なり順の変更、ロック操作ができる。非表示オブジェクトは印刷・PDF・画像書き出しに含めない。
- 図形・グラフ・画像の挿入、移動、サイズ変更、編集、削除、グループ化等にUndo/Redoを適用する。
- 同一RSFファイル内のシート間、および別のRSFファイル間でコピー・貼り付けできる。同一ファイル内でコピーしたグラフは元シートへの参照を維持する。
- 別ファイルに貼り付けたグラフは参照データをコピー先へ取り込み、元ファイルへの外部リンクを必要としない。取り込んだデータは当初グラフ内部に保持し直接編集可能。外部化するときは新しい通常のRSFシートに書き出し、以後はそのシートの編集をグラフへ反映する。
- 参照元シートを削除する場合は警告して確認する。削除後もグラフは直前の表示データを内部に保持し、削除をUndoした場合は参照を復旧する。
- 通常シートで行・列を挿入・削除した場合、その後方のオブジェクトはセル移動に追従する。行高・列幅の変更では位置だけ追従し、サイズは維持する。
- 選択オブジェクトを単独または複数まとめてPNG/SVGに書き出せる。複数選択時は配置・重なり順を維持した一枚にし、背景は標準で透明にする。

##### 6.3 二種類のロック（本スレッドで採用）

| 制御名       | 移動・サイズ変更 | 内容・書式の編集 | 一覧での選択・確認 |
| ------------ | ---------------- | ---------------- | ------------------ |
| 配置を固定   | 禁止             | 許可             | 許可               |
| 編集をロック | 禁止             | 禁止             | 許可               |

- **確定：** 二種類のロックを別機能として提供する。両方が有効なら強い方の「編集をロック」を適用する。シート全体の編集制限や内容を読めなくする暗号化とは区別する。
- **提案：** プロパティとオブジェクト一覧で名称・状態を統一し、保存・再読込・コピー後にも意図した状態を維持する。

#### 7. Markdown、印刷・PDF

##### 確定

- MarkdownのWYSIWYGエディタを追加案に含める。Markdownの追加機能はRSF側で扱う。
- 印刷とPDF出力を追加案に含める。図形・グラフ・画像はセル等とともに表示上の配置に従って出力し、非表示オブジェクトは出力しない。

##### 提案・受け入れ観点

- Markdownは編集画面から保存・再読込後も本文と意図した表示を維持する。スクリプト等をMarkdownから実行しない。
- 印刷・PDFの対象シート、ページ範囲、拡大縮小、改ページと、閲覧不可シートの扱いを指定・確認できるようにする。

#### 8. データ管理

##### 8.1 履歴プレビューの差分

- **確定：** バージョン履歴プレビューに差分ハイライトを追加する。
- **提案：** 比較対象の版と変更箇所を識別可能にし、プレビュー閲覧だけでは復元や保存を実行しない。シート構成やオブジェクトの差分を表示する範囲は詳細設計で定義する。

##### 8.2 スキーマ定義とバリデーション

- **確定：** スキーマ定義とバリデーションをRSFの追加案に含める。
- **提案：** シートの列ごとに型・必須・許容値等の規則を定義し、結果には対象シート・セル・理由を示す。検証は値を自動修正・型変換しない。規則の保存形式と対象範囲は詳細設計で確定する。

##### 8.3 SQLクエリビルダー

- **確定：** 機能追加案に含める。対象データと実行方法は未決定。
- **提案：** 通常のRSFシートを対象に、読み取り専用の抽出・絞り込み・並べ替え・集計を画面上で組み立て、結果をプレビューする。外部データベース接続、更新SQL、任意SQL入力を含めるかは別途判断する。

#### 9. 共同編集・クラウドストレージ

##### 確定

- 共同編集は明示的に有効化する別モードとし、通常のローカル完結動作と区別する。
- 対応クラウドストレージの追加を要求一覧に含める。追加先は未決定。

##### 提案・受け入れ観点

- 共同編集の開始・停止、参加者と権限、変更の同期、競合、接続断、保存先、履歴の扱いを利用者が確認できるようにする。
- 暗号化RSFやシート単位の保護を共同編集でどう扱うかが確定するまで、暗号化されたデータを安全に共有できるとは仕様上保証しない。
- ストレージ追加時には、既存の連携先との機能差、認証、開く・保存・上書き、アクセス取消し、オフライン時の動作を個別に定義する。

#### 10. CSV編集専用ミニマル版

##### 確定

- 通常版とは別の `file://` 対応配布物として、CSV編集に特化したミニマル版を設ける。収録する機能の範囲は未決定。

##### 提案・受け入れ観点

- CSVの読み込み・編集・書式保持・手動保存を中心に収録し、RSF専用機能、共同編集、クラウド連携等の採否を機能表で明示する。
- 通常版とのCSVの保存結果を同一入力で比較し、ミニマル化によって書式保持が後退しないことを試験する。

#### 11. 未決定事項とレビュー項目

以下は優先順位・スコープ・順序の決定とは独立した、仕様の未決事項である。ここで提案した選択肢を自動的に採用しない。

1. 暗号化RSFの形式、既存RSFとの互換性、パスワード・鍵の扱い、および共同編集との両立方針。
2. シート単位の保護で、シート名以外のメタデータ、数式参照、検索、履歴、出力をどこまで隠すか。
3. フォルダ削除時のシートの扱い、横／縦タブ配置の設定保存先、主要フォント候補の具体的な一覧。
4. Markdown WYSIWYGの編集対象と保存表現、印刷・PDFのページ設定、履歴差分に含める対象。
5. スキーマの規則の種類・保存位置・検証の実行タイミング。
6. SQLクエリビルダーの対象と実行方法。上記の読み取り専用RSF案を採用するか。
7. 共同編集の参加者・権限・競合・同期・暗号化との関係。追加するクラウドストレージの提供元。
8. ミニマル版の収録機能と、通常版との共通部分・除外部分。

#### 12. 仕様確定の判定

#### 既存方針・決定とのぶつかり

1. **オフライン保証 vs 共同編集**: CLAUDE.md は「offline / no-runtime-network guarantee」を守るとし、`check:dist` が強制している。共同編集は明示的な別モードとしても通信が要る。Drive 連携がすでにどう例外扱いされているかに揃えるか、ミニマル版と同様に別配布にするかの判断が要る。
2. **暗号化は高リスク扱い**: CLAUDE.md の High-risk（secrets/crypto）と RSF 形式の変更に当たり、人の承認が前提。暗号方式（例: WebCrypto の AES-GCM ＋ パスワード由来の鍵）の選定も要決定。
3. **「読めない」シート保護は実質シート単位の暗号化**: パスワードで隠すだけだとファイルを直接読めば中身が見えるので、ファイル全体の暗号化と同じ仕組みの上に作る必要がある。既存の「シートをロック」（パスワードなし）とどう併存させるか（置き換えか、閲覧のみ＋パスワードとして拡張か）も要決定。
4. **フォントの保存先**: 現在フォントは表示設定（シート > ファイル > ブラウザ、決定済み）。ドラフトはセル・文字単位のフォント指定を RSF に保存する前提なので、書式としてのフォントと表示既定のフォントの2層になる。
5. **入力規則の永続化**: 現在は意図的にセッション限定。スキーマを RSF に保存するなら、既存の入力規則も保存・行列追従させるかを合わせて決める必要がある。
6. **ツールバー設定は端末側保存**: `file://` では localStorage が他のローカル HTML と共有されるため、SQL 履歴と同様にセッション限定になる点に注意。

この突き合わせで「先に決めると効く」とした共同編集・暗号化・オブジェクト保存形式は、上の「決定事項」で決まった。
