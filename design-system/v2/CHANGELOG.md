# Changelog

## 2.5.0 — 2026-10-06

ダイアログとサイドパネルの使い分けと、その中の並べ方・余白・ボタン・幅の規則を足しました。
判断の根拠は `docs/decisions.md` の「2.5.0 の見直し」（G-19〜G-23、D-46〜D-51）にあります。
トークンと規則の追加が中心で、利用側のコードを直さなくても使えるので、マイナー版です（`.rs-field--inline` の廃止を除く）。

### 規則
- **ダイアログかサイドパネルか（D-46）** — 答えるまで進めないもの（確認・操作を始める短い入力・選ぶとすぐ閉じる選択・OK/キャンセルの設定）だけをダイアログに。シートを見ながら使うもの（読みながら作業する説明・結果を見ながら調整する設定・行き来する一覧）はサイドパネルに。
- **フォームの並べ方（D-47）** — ラベルは入力欄の上、入力欄は全幅、補足はその下。チェックボックスとラジオボタンはラベルが右。横に並べるのは短く関係の深い項目だけ（ダイアログは 2 列まで）。まとまりには見出しと区切り線。
- **余白（D-48）** — ラベルと入力欄 `--label-gap`、項目の間 `--stack-gap`、まとまりの間 `--section-gap`、器の内側 `--inset` × `--inset-inline` の 4 つだけ。
- **ボタン（D-49）** — 右下に右寄せ。確定する操作が右端、その左にキャンセル、どちらでもない操作は左端。主な操作は 1 つだけ。「OK」は使わない。最小幅 80px。
- **ダイアログの幅（D-50）** — 小 360px・中 480px（既定）・大 640px。パネルの既定は 380px。
- **見た目を揃える（D-51）** — ダイアログのタイトルとボタン欄に地色の帯を付けず、パネルと同じ `--bg-raised` の上に 1px の線で区切る。

### 追加
- アプリ：`--section-gap`（密度 8 / 16 / 24px）、`--label-gap`（4px）、`--field-col-gap`（12px）、`--button-gap`（8px）、`--button-min-w`（80px）、`--dialog-w-sm` / `--dialog-w-md` / `--dialog-w-lg`（360 / 480 / 640px）、`--panel-w`（380px）。
- 部品：`.rs-form`・`.rs-section`・`.rs-section__title`・`.rs-field-grid`・`.rs-actions__start`、`.rs-dialog--sm`・`.rs-dialog--lg`。
- 説明書：「レイアウト」に「ダイアログかサイドパネルか」と「ダイアログとパネルの中の並べ方」。

### 変更
- `.rs-label`：本文の大きさ・既定色 → `--text-caption`・太字・`--fg-muted`（アプリのパネルに合わせた）。
- `.rs-field` の間隔：`--space-1` → `--label-gap`。`.rs-btn` に最小幅。`.rs-actions` の間隔を `--button-gap` に。
- `.rs-dialog`：既定の幅を `--dialog-w-md` に。タイトルとボタン欄を 1px の線で区切り、上下の余白を `--inset` に揃えた。
- `.rs-dock`：幅を `--panel-w`、地を `--bg-raised` に。
- `--stack-gap` の説明を「フォームの項目の間」に。

### 削除
- `.rs-field--inline`（ラベルを横に置く並べ方）。`.rs-dialog--wide`（`.rs-dialog--lg` に置き換え）。

## 2.4.0 — 2026-09-26

縞模様の行が 2.0.0 から濃くなって困る、見出しとグリッドの外をもっと濃くしてほしい、というメンテナーの指摘に合わせて、表のキャンバスの色を見直しました。
判断の根拠は `docs/decisions.md` の「2.4.0 の見直し」（G-17・G-18、D-43・D-44）にあります。
トークンの追加と値の変更だけなので、マイナー版です。

### 規則
- **縞模様の濃さ（D-43）** — 縞模様は 3 段階。薄い（既定、2.0.0 より前と同じ見た目）・普通（これまでの `--canvas-row-alt`）・濃い。
- **見出しとグリッドの外（D-44）** — 行番号と列番号の地を、どの縞模様よりも濃くした。見出しどうしの線は `--canvas-grid-strong`。
  最後の行・列より外は `--canvas-outside` で塗り、表の端がわかるようにした。

### 追加
- アプリ：`--canvas-row-alt-light`（light paper.50 の 50%／dark ink.900 の 50%、`--canvas-bg` の上に重ねる）、`--canvas-row-alt-strong`（paper.100／ink.800）、`--canvas-outside`（paper.300／ink.1000）。
- 監査：薄い縞と濃い縞の上のセルの文字 2 組。

### 変更
- `--canvas-header-bg`：paper.50／ink.900 → paper.200／ink.800。
- `--canvas-header-selected-bg`（light）：green.100 → green.200（濃くした見出しの中で選択がわかるように）。

## 2.3.0 — 2026-09-26

LP リニューアルでデザインの方向性（AC2）を決めたのに合わせて、ブランドの規定を改訂しました。
判断の根拠は `docs/decisions.md` の「2.3.0 の見直し」（G-13〜G-16、D-38〜D-42）にあります。
トークンと部品の追加と見た目の変更だけで、利用側のコードを直さなくても使えるので、マイナー版です。

### 規則
- **ボタンの形（D-38）** — `.rb-btn` の角丸を `--radius-lg`（8px）から `--radius-full` にした。
- **ファーストビューのパネル（D-39）** — Mist の地に大きな角丸をつけた `.rb-feature` を追加。1 ページに 1 つ、ファーストビューだけに使う。
  「緑は 1 画面に 1〜2 か所」は濃い緑（`--accent`）の規則とし、淡い緑のパネルは別に 1 つまで認める。
- **カードと額縁の角丸（D-40）** — `.rb-card`（12px）と `.rb-shot`（16px）を `--brand-radius-card`（18〜24px）に。
- **動くデモの例外（D-42）** — 「画面は実物だけ」の例外として、LP のファーストビューの動くデモに限り、
  実物の画面を HTML・SVG・CSS で描き起こせるようにした。アプリのトークン、`src/locales` の文言、実際にある機能と操作だけで描き、撮影した画面と見比べて確かめる。
- **見出しの言葉（D-41）** — ブランドの核の一文は判断の軸とし、LP の見出しには使わない。製品の種類は「表計算ソフト」と呼ぶ。

### 追加
- 共通基盤：`--bg-feature`（light green.100 / dark green.900）。
- ブランド：`--brand-radius-panel`（28〜40px）、`--brand-radius-card`（18〜24px）、部品 `.rb-feature`。
- 監査：`--bg-feature` の上の文字 3 組（`fg-default`・`fg-muted`・`accent-subtle-text`）。ブランド 8/8。

## 2.2.0 — 2026-09-26

2.1.0 の密度は 1 段 4px で、3 つの密度の見分けがほとんどつかず、タッチでは密度がまったく効きませんでした。
判断の根拠は `docs/decisions.md` の「2.2.0 の見直し」（G-11・G-12、D-36・D-37）にあります。
利用側のコードを直さなくても使えるので、マイナー版です。

### 規則
- **密度の刻み（D-36）** — 1 段 4px → 8px。バー 24 / 32 / 40px、コントロール 24 / 28 / 36px、入力欄 24 / 32 / 40px、
  状態バー 24 / 24 / 32px、`--inset` と `--stack-gap` 4 / 12 / 20px。standard の値は変えない。
- **タッチの密度（D-37）** — 粗いポインタにも密度ごとの値を置く。standard はバー 40px・コントロール 36px・入力欄 40px・状態バー 36px（2.1.0 は密度にかかわらず 48 / 44 / 44 / 40px）。
  同じ 8px の刻みで、下限は 28px（compact のバー 32px、comfortable のバー 48px）。

## 2.1.0 — 2026-09-26

2.0.0 をアプリと LP に適用し終えたあとで規定全体を見直し、実際と合わない点と規定どうしの不整合をそろえました。
判断の根拠は `docs/decisions.md` の「2.1.0 の見直し」（G-1〜G-10、D-27〜D-35）にあります。
利用側のコードを直さなくても使えるので、マイナー版です。

### 規則
- **版とディレクトリ（D-27）** — 版は利用側に必要な作業で決める。ディレクトリはメジャーごとに 1 つにし、
  `design-system/2.0.0/` を `design-system/v2/` に改めた。ブランドガイドラインも DS と同じ版番号を使う（独自の v3.0 をやめる）。
- **密度（D-28）** — 「standard から 1 段ごとに縦の寸法を 4px、高さは 24px 以上」の 1 つの規則から値を計算する。
  comfortable のバーと入力欄 40 → 36px、状態バー 32 → 28px。横の余白は密度で変えない（`--control-px` は 8px 固定）。
- **タッチ（D-29）** — `--target-min` 24px、`--target-touch` 44px、`--target-touch-dense` 40px を追加。
  粗いポインタの密度の値もここから導く（状態バー 32 → 40px）。
- **ブレークポイント（D-30）** — アプリと LP が実際に切り替える幅に：`--bp-sm` 32.5em、`--bp-md` 43.75em、`--bp-lg` 56.25em（`--bp-xl` は予約）。
- **意味色（D-31）** — 段階と役割の対応（印 600 / 300、文字 700 / 300、淡い面 100 / 900）で選ぶ。
  `--success-text` と `--success-subtle` を追加。`--warning` を amber.600、`--warning-text` を amber.700 に。`--ref-3` と `--canvas-find-current` を amber.600 に。
- **タッチの文字（D-32）** — 粗いポインタではすべての段が +2px・行送り +4px（title 18px、heading 22px を追加）。
- **LP の行送り（D-33）** — 読む文 1.75、見出し 1.3 の 2 つだけ。`--leading-display` を追加。

### 追加
- 共通基盤：`--success-text` `--success-subtle` `--target-min` `--target-touch` `--target-touch-dense` `--leading-display`。
- アプリ：`--inset-inline`（ダイアログと docked パネルの左右の余白、16px）。

### 修正
- 値の出典を 1 か所に（D-34）：`--focus-width`（＝ `--stroke-medium`）・`--focus-offset`・`--icon-stroke` を `tools/source/` に移し、共通基盤の文書のフォント表を生成物にした（D-24 のあとも古い連鎖のままだった）。
- 監査（D-34）：アプリの `check:contrast` の組をすべて DS の監査に含めた。共通基盤 94/94、アプリ 99/99、ブランド 2/2。
- 文書（D-35）：ブランドの基準色の数、重なり順の説明、未来形のままだった記述、README の 1.0.0 の記述、アプリの文書のブレークポイントと文書タブの配置。
- 部品：`.rs-dialog` `.rs-dock` の左右の余白を `--inset-inline`、上下を `--inset` に。ポップオーバー・カード・フィールドセットの左右は `--space-3`。

## 2.0.0 — 2026-09-26

v1.0.0 を再評価し、表計算の密度に合わせて作り直しました。あわせて、ブランド（LP など）と
アプリ UI の規定を分け、両方が使う部分を共通基盤にまとめました。
判断の根拠は `docs/decisions.md`、調査は `docs/research.md`、
移行とアプリ・LP への適用計画は `docs/migration.md` にあります。

### 構成
- **3 層に分割** — `foundations/`（共通基盤：色・書体・余白・形・線・動き・アイコン・ロゴ）、
  `brand/`（ブランドガイドライン v3.0：LP・ドキュメント・ストア掲載）、
  `app/`（アプリ UI のデザインシステム）。層は基盤に足すだけで、上書きしない。
- **ブランドガイドライン v3.0** — v2.0 の文字規定（Inter・500/600・11px）を、実際に表示される
  OS 標準の書体と 400/700・最小 12px に合わせて書き直した。ロゴとアプリアイコンの規定は維持。

### 破壊的変更
- **トークン名** — `--chrome-*` を `--bg-*` `--fg-*` `--border-*` に、線の太さ
  `--border-thin/thick` を `--stroke-thin/medium/thick` に。
- **文字（アプリ）** — 本文 16 → 14px、補助 14 → 12px。役割名 caption / body / title / heading。
  文字の下限は日本語も 12px。セルは 12px × 表示倍率のまま。
- **密度** — compact / standard（既定）/ comfortable。バー 28/32/40、バー内コントロール 24/28/32、
  フォーム 28/32/40。`--control-h` と `--field-h` の 2 系統。
- **角丸** — lg 10 → 8px、xl 14 → 12px、2xl 16px を追加。
- **重なり順** — アプリの実際の層構造に合わせて `--z-*` を再定義（アプリ層）。
- **大文字の英字ラベルの字間** — 0.04 → 0.08em。
- **暗いテーマの副次テキスト** — すべての背景で 4.5:1 に。
- **バナー** — シート用の `--state-*` ではなく `--*-subtle` を使う（hybrid で警告文が 1.53:1 に
  なっていた不具合の修正）。

### 追加
- 共通基盤：余白 2px・6px・80px・96px、`--stroke-medium`、`--icon-*`、`--bg-hover` `--bg-pressed`、
  `--inverse-*`、`--brand-*`（基準色 5 つ）、`--font-code`、`--text-min`、色 `ink-150` `ink-250` `violet` `teal`。
- アプリ：キャンバスの状態一式（範囲選択・検索・数式の参照・数式・コメント・編集済み・エラー・構文色）、
  テーマに依存しない文書の色 65 色と条件付き書式の既定色、グリッドの寸法、部品（メニュー・タブ・
  数式バー・docked パネル・ツールチップ・進捗・空の状態・グリッド・ソースエディタ）。
- ブランド：流体的な文字サイズ、ページの幅と区切り、44px のボタン、見本の影、`rb-` 部品。
- Design Tokens Format Module 2025.10 形式の JSON（各層の `tokens/`、`$schema` 付き）。
- 生成・監査ツール `tools/build.mjs` と、値の出典 `tools/source/{foundations,app,brand}.mjs`。

### 検証
- コントラスト監査：共通基盤 76/76、アプリ 96/96、ブランド 6/6 合格。
- 手書きの CSS（アプリ 3 ファイル・ブランド 1 ファイル）に色のリテラル 0 件。
- `node design-system/v2/tools/build.mjs --check` で生成物が最新であることを確認。

### 変更なし
- ブランドの色相と段階、ロゴタイプ、アプリアイコン（ファイルは 1.0.0 と同一）。
