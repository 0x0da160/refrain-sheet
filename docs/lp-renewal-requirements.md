# LP renewal — requirements definition / LPリニューアル 要件定義書

**Status: draft (v0.4, 2026-09-26). No landing-page code is changed by this document.**

## English (summary)

A full rebuild of the Refrain Sheet landing site (`site/` → `landing/`,
served at `refrain-sheet.com` on Cloudflare Pages), derived from a
requirements interview with the maintainer. Goals: stronger first view,
refreshed design, clearer message, better conversion and SEO. Primary CTA is
"open the app"; secondary CTAs are the offline HTML download and GitHub.
Japanese and English are kept; the no-external-resources rule is kept.
Analytics moves from opt-in-for-everyone to region-based consent (consent
banner only for EEA/UK/CH visitors), which needs human approval as a
personal-data and deploy-config change. Design direction is decided:
mockup AC2 (C's soft rounded panels with A's trust elements). Copy speaks to
each persona through wording and context rather than by naming the audience,
and is written for people first and search second (§4.6). The message is
widened from "a CSV editor" to "a lightweight spreadsheet app that edits
CSV without breaking it": spreadsheet features widen the audience, CSV
preservation stays the lead strength. Copy favours plain, concrete words
over the abstract brand line (§1.1). Work proceeds in phases
with no deadline; quality first. Open decisions are listed in §9.

## 日本語

### 1. 背景と目的

現行LP（`site/template.html`、約14セクション・約200の翻訳キー）は情報量が多く、
**ファーストビューが弱い**こと、**デザインが古く地味**なことが課題になっている。
今回のリニューアルでは次の4つをすべて目的とする。

| #   | 目的                                      | 測り方（§8）                                        |
| --- | ----------------------------------------- | --------------------------------------------------- |
| G1  | アプリの起動率を上げる                    | LP → `app.refrain-sheet.com` のクリック率           |
| G2  | 「CSVを壊さない」という価値が一目で伝わる | ファーストビュー内のCTAクリック率、スクロール到達率 |
| G3  | デザインを刷新し、ブランドの印象を上げる  | デザイン方向性レビューで承認（§6）                  |
| G4  | 検索からの流入を増やす                    | Search Console の表示回数・クリック数               |

#### 1.1 訴求戦略（ブランドの観点からの見直し）

**CSVの非破壊編集は「強み」であって「カテゴリ」ではない。** CSVだけを前に出すと、
CSVで困った経験のある人にしか届かない。表計算ソフトとしての機能も前に出して間口を広げ、
CSVを壊さないことは一番の強みとして先頭に置く。

**言葉は、抽象より明快さを優先する。** ブランドガイドライン
（`design-system/v2/brand/docs/brand-guidelines.html`）の核のメッセージ
「あなたのデータは、あなたが変えたところだけが変わる」は、判断の軸として内部で使い、
LPの見出しには使わない。現場の担当者が一読で「何のソフトか」がわかる具体的な言葉を使う。

- **h1：** CSVを壊さず編集できる、軽い表計算ソフト
- **h1 の直前の短い説明：** ブラウザで開くだけ。無料・インストール不要
- **解決すること：** 手元の業務データを、クラウドに上げず、重いソフトを入れず、
  勝手に書き換えられる心配もなく扱えること

**呼び方の決定**

| 候補                       | 採否           | 理由                                                                                                                                 |
| -------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 表計算 / スプレッドシート  | **表計算**     | 日本の職場では「スプレッドシート」が Google スプレッドシートを指すことが多く、製品名と取り違えやすい。「表計算」は誤解のない一般名詞 |
| ソフト / アプリ / ツール   | **ソフト**     | 「表計算ソフト」が最もなじみのある組み合わせ。「アプリ」はスマホやインストールを、「ツール」は小さな道具を連想させる                 |
| （補足）インストールの誤解 | 近くの文で補う | 「ソフト」はインストールを連想させるので、h1 の直前か直後に「ブラウザで開くだけ」「インストール不要」を必ず置く                      |
| CSVエディタ                | 補助的に使う   | 検索される言葉なので、CSVのブロックの本文や title・description に入れる。見出しの主語にはしない                                      |

次の3つの柱で、ページ全体を組み立てる（見出しは具体的な言葉で書く）。

| 柱                       | 伝えること                       | 主な根拠                                                                                                                                                    |
| ------------------------ | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 表計算ソフトとして使える | ふだんの集計に足りる表計算の機能 | 55関数（SUMIFS・XLOOKUP・FILTER・UNIQUE など）、複数シート、並べ替え・フィルタ、入力規則、条件付き書式、SQL、比較、コメント、版の履歴、XLSX・JSONの読み書き |
| CSVを壊さない            | CSVは開いたときの形のまま        | バイト単位の保持、型推論をしない、文字コード・BOM・改行コードの保持、壊れたCSVの診断、保護モード                                                            |
| データを外に出さない     | データは自分のパソコンの中に     | ブラウザ内で処理、1つのHTMLファイル、オフライン、スクリプトを実行しない、オープンソース                                                                     |

誠実さもブランドの性格なので、**「大きな表計算ソフトの代わりではない」** ことは隠さずに書く。
機能を紹介するときも「完全互換」「すべて対応」のような断言はしない。書き出しが値のみであるなど、
制約は機能と並べて書く。

### 2. ターゲット

優先順位はつけず、4つのペルソナそれぞれに「自分向けの入口」を用意する。

| ペルソナ                                           | 知りたいこと                        | 対応するセクション                                            |
| -------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------- |
| 業務担当者（非エンジニア）：経理・人事・EC運営など | 自分のCSVが壊れないか、すぐ使えるか | 用途別の事例、動くデモ、3ステップ                             |
| 情シス・社内IT担当                                 | 社内に入れて安全か                  | セキュリティ・オフライン、サプライチェーン対策、OSSライセンス |
| 開発者・エンジニア                                 | 仕組み、正確さ、拡張性              | バイト単位で一致すること、RSF・数式・SQL、GitHub              |
| 手元のデータで表計算をしたい人（職種を問わない）   | 無料で、入れずに、安全に使えるか    | ヒーロー、表計算の機能、セキュリティ                          |

英語版の読者（海外ユーザー）は、上のペルソナの英語版として扱う。

各ペルソナの入口は、見出しで読者を名指しして作らない（「情シスの方へ」
「エンジニア向け」などは使わない）。その読者が気にする言葉と文脈
（「社外秘」「社内のルール」「サーバーに送信しない」「ソースコードを公開」など）で、
自分に関係のある段落だと気づけるように書く（§4.6）。

### 3. スコープ

**対象：全面的な作り直し**（構成、コピー、デザイン、ビジュアル、技術基盤）。

- 対象：`site/template.html`・`i18n.js`・`styles.css`・`main.js`・`consent.js`、
  `scripts/build-landing.mjs`、`site/assets/`、関連するテスト
- 付随して更新：`privacy.html` / `terms.html`（解析方針の変更に合わせる。デザインも統一）
- 対象外：アプリ本体（`src/`、`wasm/`）、`app.refrain-sheet.com` のデプロイ

### 4. 機能要件

#### 4.1 ページ構成（案。コピーは別途レビュー）

現行の14セクションを、§1.1 の柱に沿って次の8ブロックにまとめる。

1. **ファーストビュー**：短い説明 + h1（何のソフトか）+ 表計算の画面を使った動くデモ + 主CTA・副CTA
2. **3つの柱**：CSVを壊さない／表計算ソフトとして使える／データを外に出さない を1行ずつ
3. **表計算の機能**：数式と関数、並べ替え・フィルタ、入力規則・条件付き書式、SQL、比較、
   コメント・版の履歴、XLSX・JSONの読み書き、メモのシート。「大きな表計算ソフトの代わりではない」も添える
4. **CSVの保持**：「直すのは1セル、変わるのもその1セルだけ」を差分の図で見せる。
   先頭ゼロ・文字化け・改行コードの事故も、ここで扱う（暗い帯で製品を実演する）
5. **用途別の事例**：会計・税務／人事・給与／受発注・EC／基幹システムの連携／原因調査。
   CSVの手直しと、表計算での集計の両方の例を入れる
6. **セキュリティ・オフライン**：送信しない、実行しない、ソースコードを公開、
   Google ドライブ連携は使うときだけ、サプライチェーン対策
7. **比較・FAQ**
8. **最後のCTA**：3ステップ + アプリを開く／ダウンロード

#### 4.2 CTA

- **主CTA：** 「ブラウザで開く」→ `https://app.refrain-sheet.com/`
- **副CTA：** オフライン版HTMLのダウンロード、GitHubリポジトリ
- 主CTAはファーストビューと最後のCTAに必ず置く。スクロール中も押せる
  固定ヘッダーのCTAも検討する
- ダウンロード先は、GitHub Releases の最新版アセットへの直接リンクにするか、
  Releasesページへのリンクにするかを決める（§9）

#### 4.3 ファーストビューの動くデモ

- 表計算の画面（数式・フィルタ・条件付き書式・シートのタブ）を主役にし、
  「CSVを開く → 集計する → 元のCSVはそのまま」という流れをアニメーションで見せる。
  CSVの差分（1セルだけ変わる）の実演は §4.1 のブロック4で行う
- 作り方：インラインのSVG・HTML + CSSアニメーション（必要なら少しだけJS）。
  **動画ファイルや外部のプレイヤーは使わない**
- `prefers-reduced-motion` のときは止めた状態（最終フレーム）で見せ、
  一時停止ボタンをつける（WCAG 2.2.2）
- デモの画面は Refrain Sheet 自身のUIを描いたものにする。
  Excelの画面を再現しない（`knowledge/decisions/ip-risk-policy.md`）
- 日本語版と英語版で、デモの中の文字とサンプルデータを切り替える

#### 4.4 多言語

- 日本語（`/`）と英語（`/en/`）を維持する。ページ内の言語切り替え、
  `hreflang`、canonical も維持する
- 翻訳キーは日英で同じ集合にし、テストで確認する（現行の方針を引き継ぐ）

#### 4.5 アクセス解析（要承認）

- **方針：地域で分ける。**
  - EEA・英国・スイスからの訪問：これまでどおりオプトインの同意バナーを出し、
    同意してからGAを読み込む
  - それ以外の地域：同意なしでGAを読み込む。フッターからいつでも
    計測を止められる（オプトアウト）ようにし、プライバシーポリシーで通知・公表する
    （電気通信事業法の外部送信規律）
- 国の判定：Cloudflare Pages Functions で `CF-IPCountry` ヘッダーを読み、
  HTMLかレスポンスヘッダーで判定結果を渡す。**判定できなかったときは
  同意が必要な地域として扱う**（安全側に倒す）
- `privacy.html` と `knowledge/operations/security-threat-model.md` の記述を
  あわせて更新する
- CLAUDE.md の定める高リスク変更（個人データ、デプロイ設定）に当たるため、
  **実装の前に人間の承認を得る**。法的な判断は専門家に確認してもらうことを推奨する

#### 4.6 ライティングとSEO

優先順位は **人への訴求 > 検索エンジン** とする。検索のために読みにくくしない。

- **読者を名指ししない。** ペルソナは言葉と文脈で呼び分ける（§2）。
- **検索されやすい言葉を、見出しと本文に自然に入れる。** 主な言葉は
  - 間口を広げる言葉：「表計算ソフト」「無料」「インストール不要」
    「ブラウザ」「オフライン」「関数」「集計」
  - 強みを示す言葉：「CSV 編集」「CSVエディタ」「文字化け」「先頭ゼロ（が消える）」
    「Shift_JIS」「改行コード」
    同じ言葉を不自然に繰り返さない。
- **h1 で「何のソフトか」を言い切る。** h1「CSVを壊さず編集できる、軽い表計算ソフト」、
  その直前の短い説明「ブラウザで開くだけ。無料・インストール不要」。
  抽象的なスローガンや比喩を見出しにしない。各ブロックの h2 も具体的にする
  （例：「集計も、整理も、見比べも。表計算ソフトとして、ここまでできます。」
  「CSVを直すのは1セル。変わるのも、その1セルだけ。」）。
  見出しの階層（h1 → h2 → h3）を飛ばさない。
- **悩みの言葉で書く。** 検索する人は機能名ではなく症状で探す
  （「JANコードが 4.9E+12 になる」「社員名簿が文字化けする」）。
  用途別の事例とFAQは、症状の言葉を見出しに使う。
- **`<title>` と meta description** は、今のものが持つ言葉（CSV 編集・無料・Shift_JIS・
  先頭ゼロ・改行コード・インストール不要）を引き継ぎ、新しいコピーに合わせて書き直す。
  title は32文字前後、description は120文字前後を目安にする。
- **FAQ** は、実際に検索される質問の形で書き、構造化データ（FAQPage）と一致させる。
- **英語版** は逐語訳しない。英語で検索される言葉
  （"edit CSV without Excel changing it"、"keep leading zeros"、"Shift_JIS CSV editor" など）
  を調べてから書く。
- **文言のルール**：`knowledge/ui/ui-writing-and-wording.md` の原則に従う
  （落ち着いた敬体、根拠のない断定をしない、「アップロード」は実際に送信するときだけ使う）。
  訴求文と、アプリの操作文言は混ぜない。
- **事実だけを書く。** 「送信しない」「実行しない」などは、実装と
  `knowledge/operations/security-threat-model.md` に合っていることを確かめる。
  Google ドライブ連携のような例外は省略しない。

### 5. 非機能要件

| 分類             | 要件                                                                                                                                                                             |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 外部リソース     | CDN・ウェブフォント・外部画像は使わない（`tests/landing-external-resources.test.ts` を維持）。例外は §4.5 のGAだけ                                                               |
| 性能             | 目標：モバイルでLCP 2.0秒以下、CLS 0.1以下。CSSとJSを合わせた転送量は圧縮後150KB以下（目安。現状を測ってから確定）                                                               |
| アクセシビリティ | WCAG 2.2 AA。キーボードで操作でき、コントラスト比を満たし、アニメーションを止められる                                                                                            |
| レスポンシブ     | 360px幅から問題なく表示できる。横スクロールが出ない                                                                                                                              |
| テーマ           | ライトとダーク（`prefers-color-scheme`）                                                                                                                                         |
| SEO              | 既存のURL（`/`、`/en/`、`/privacy.html`、`/terms.html` と英語版）を変えない。構造化データ（SoftwareApplication・FAQ）、OGP、sitemap を維持する。`*.pages.dev` は引き続き noindex |
| セキュリティ     | インラインで評価される文字列（`eval` など）を使わない。CSPを入れることも検討する                                                                                                 |
| ライセンス表記   | すべてのソースファイルの先頭に `// SPDX-License-Identifier: MIT`                                                                                                                 |
| IPリスク         | Excelの画面の再現、Microsoftの素材、「Excel互換」とうたう表現を使わない                                                                                                          |

### 6. デザインの方向性（決定：AC2）

4案（A. 信頼感・堅実／B. モダン・開発者ツール風／C. 親しみやすさ／
D. design-system v2 に忠実）と、A×C のミックス3案をモックアップで比べ、
**AC2「Cの器 × Aの信頼要素」** に決めた。

- **Cから取るもの**：Mist（`#DAECD8`）の大きな角丸パネル、丸いボタン、角丸の大きいカード、
  やわらかい余白
- **Aから取るもの**：アプリ画面風の表のプレビュー、「差分 1セル」の表示、
  「先頭ゼロ・文字コード・改行コード：そのまま」の表示、根拠を並べたセクション
- 配色は design-system v2 の Preserve green・Paper・Ink・Mist の範囲に収める
- ブランドガイドラインとの差（丸いボタン、Mist の大きなパネル）は、フェーズ1で
  ガイドラインを改訂するか、ボタンの角丸を 8px に戻すかを決める
- 表計算の機能を見せるブランド訴求版（`AC2-Brand`）を、ページ構成のたたき台にする
- ダークテーマ版と、360px幅のレイアウトはフェーズ1で設計する

決めた方向性は `design-system/v2/brand/` のトークンに反映する。LPだけで使う値は
brand レイヤーに置き、アプリと共有している foundations は壊さない。

### 7. 技術方針（おまかせ → Claude の推奨）

**推奨：フレームワークを入れず、今のビルドの仕組みを作り直す。**

- 理由：`knowledge/decisions/no-ui-framework.md` の依存を最小限にする方針と、
  サプライチェーンのゲート（`npm ci --ignore-scripts`、EOL台帳）に合っている。
  Astro などを入れると、新しい依存のEOL管理とSBOMの対象が増える
- 具体的には：
  - `site/` を部品（partials）ごとのファイルに分け、`build-landing.mjs` で組み立てる（jsdom は今も使っている）
  - CSSは design-system v2 のトークンを土台にして、セクションごとに書き直す
  - JSはバニラで、デモのアニメーションと言語切り替えと同意の処理だけにする
- 例外：国の判定のための Pages Functions（`functions/`）を1つ加える（§4.5・要承認）

### 8. KPIと計測

- 期限は設けず、品質を優先する
- 主なKPI：LP → アプリの起動クリック率（公開前後で比べる）
- 補助KPI：ダウンロードとGitHubのクリック数、スクロール到達率、Search Console の指標
- 解析の方針が変わるので、変更の前後で数字を単純に比べられない点に注意する
  （同意率の変化の影響を受ける）

### 10. 進め方（段階的に公開）

| フェーズ | 内容                                                                     | 完了の条件                                                |
| -------- | ------------------------------------------------------------------------ | --------------------------------------------------------- |
| 0        | デザイン案のモックアップ、コピー案                                       | Q1（決定済み）・Q4 が決まる                               |
| 1        | 基盤：部品化したビルド、トークン、レイアウト、ファーストビューと動くデモ | 既存テスト + 外部リソーステスト + `ui:check` がすべて通る |
