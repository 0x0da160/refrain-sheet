DESIGN SYSTEM · v1.0.0 · 2026-09-22

Refrain Sheet
Design System

ブラウザ上で動く書式保持CSVエディタのための、トークン・コンポーネント・ アクセシビリティ基準の一式。ブランドガイドラインを唯一の出典として生成しています。

作り方対象環境形 色文字余白と密度 面部品レイアウト アクセシビリティ性能実装 運用

作り方

dembrandt の6ステージを順に通しています。実行したステージと、 省いたステージとその理由を明示します。

ステージ名称状態参照した規範と結論
Stage 1Brand Foundation実行brand-visual-language / algorithmic-color-palette / color-mode-and-theme
形の言語はアイコンから読み取り済み。色は Oklab スケールへ拡張し、3テーマを確定。
Stage 2Design Tokens & Scales実行modular-scale-typography / sizing-units / elevation-and-depth / button-states / component-family-consistency / status-colors-and-errors / surface-separation

アプリシェル、密度3段、2軸スクロールの唯一の例外を定義。
Stage 4Components & Interaction実行app-shell / operational-expert-tool-ui / data-display-and-selection / form-design / modal-and-overlay-patterns / notifications-and-recovery
熟練者向けの密度と常時可視の状態表示、オーバーレイ階層、復旧経路を規定。

規範は証拠であって法ではありません。画面で再現できる制約 （フォントに存在しないウェイト、OSの描画、コントラスト）が規範と衝突した場合は制約が優先です。 本書で規範から外した箇所は、すべてその理由を併記しています。

対象環境

主対象

Windows 11 / Chrome（最新2バージョン）。デスクトップの業務利用が中心で、 1日中開かれることを前提にしています。

対応

iOS Safari / Android Chrome、macOS Safari・Chrome、Firefox。 モバイルは閲覧と軽い修正を想定し、一括操作などは折りたたみます。

前提

Webフォントは1つも読み込みません。UIはOS標準フォントのみで成立します。 ロゴタイプはアウトライン化済みSVGのため、フォント環境に依存しません。

形の言語

アイコンがすでに答えを持っています。外側はやわらかく、データは直角。 シェルの部品は6〜14pxの穏やかな丸みを持ち、グリッドのセルは角を持ちません。

トークン値用途
--radius-cell0データグリッドのセル・行・列ヘッダ
--radius-xs2pxセル内チップ、ステータスドット枠
--radius-sm4pxウェル、インセット領域
--radius-md6pxボタン、入力、セレクト、トグル（コントロール基準）
--radius-lg10pxカード、パネル
--radius-xl14pxモーダル、ドロワー、ポップオーバー
--radius-full999pxピル、アバター、ステータスドット
入れ子の角は同心にします。外側の半径 = 内側の半径 + その間の余白。 border-radius: calc(var(--radius-md) + var(--space-4)) のように calc() で導き、数値を焼き付けません。
境界線の太さは --border-thin と --border-thick の2段だけです。 1,2,3,4px と刻みません。

色

Oklab（極座標 OKLCH）で設計し、sRGB 16進で納品します。中間色は Paper（暖色）とInk（寒色）の二極。テーマはこの2極の組み合わせです。 詳細な設計根拠はブランドガイドラインを参照してください。

ウェイトは400と700の2段しかありません。 BIZ UD系に500・600は存在せず、font-weight: 500 は400に落ちます （Yu Gothic UI の Semibold は別ファミリ名なので font-weight では届きません）。 したがって本システムは中間ウェイトを一切使わず、 階層は「サイズ・色・余白」で作ります。 「補助テキストは最低500ウェイト」という一般則はこの環境では実現できないため、 代わりに色のコントラストで担保しています （--chrome-text-muted は本文の下限4.5:1を満たす値に固定）。
数字を揃えるには等幅フォントを使うこと。 BIZ UDPGothic に tnum は存在しないため、 font-variant-numeric: tabular-nums は無効です。桁を揃える必要がある数値は .rs-data（BIZ UDGothic）を使ってください。BIZ UDGothic は英数が半角固定・ かな漢字が全角固定なので、和文を含む列でも桁が揃います。 zero（スラッシュ付きゼロ）は3書体とも実在するため常時有効にしています。

密度

密度が変えるのは高さと余白だけで、文字サイズは動かしません。 熟練者向けに compact を用意しますが、読みにくくして詰めることはしません。

密度コントロール高行高 想定
compact32px28px マウス操作のデスクトップ。1画面に多くの行を出す
comfortable36px34px 既定
spacious44px44px タッチ、または視認性を優先する場合
指先は細かく狙えません。@media (pointer: coarse) では 密度の指定に関わらず44pxを下回らせない上書きが入ります。密度トグルはタッチ端末では 見た目が変わらないことがありますが、これは意図した動作です。

面の分け方

面を背景から切り離す方法は3つしかありません。 1つの面には1つだけ使います。3つ重ねた面が「うるさい」UIの最大の原因です。

手段読ませるもの使う場所クラス
境界線面の終わりパネル、カード、表、フォーム .rs-panel .rs-card
エレベーション面の高さモーダル、ドロワー、ポップオーバー .rs-raised
地色面の所属ウェル、サイドバー、交互行 .rs-well
明色テーマの浮いた面だけは「境界線＋影」の併用が正解です （影だけでは白地に沈むため）。このとき地色はページ色から1段以内に留めます。
不透明度は状態です。無効・読み込み中・ドラッグ中だけに使い、 色を薄くする目的では使いません。薄い色は必ず解決済みのトークンとして定義します。

アクセシビリティ

WCAG 2.2 レベルAA を出荷条件にします。これは満たせなかったら出さない、 という意味の条件です。

知覚できる

本文4.5:1／UI部品3:1（監査 78/78 合格）。 色だけで情報を伝えません——差分セルは色に加えて記号と打ち消し線を持ちます。

操作できる

全操作がキーボードで到達可能。フォーカスリングは消しません。 タッチ操作領域は44px以上。「本文へスキップ」を最初のフォーカス対象に置きます。

理解できる

<html lang="ja">。全入力に可視ラベル。 エラーは aria-describedby で入力と結び付け、文章で理由を述べます。

堅牢である

ネイティブ要素を使い、ARIAは足りない所だけ。 動的更新は role="status"／role="alert" で読み上げます。

運用

色のリテラルを書かない

トークンの現在値とたまたま一致する生の色は、テーマに追随できない形で 書かれたそのトークンです。明色テーマで見ると単に間違っているのではなく、 沈んでいるべき面が浮いて見えるなど関係が反転します。しかもトークン監査では原理的に見つかりません。 だから規律ではなく機械で止めます。

python tools/lint_tokens.py        # tokens.css 以外のリテラル色を検出。予算は0件
